# UI/UX contract: единый интерфейс Portal

**Область:** код тестовой Nexus-ветки, не опубликованный production-релиз. Источники истины:
`frontend/src/styles/tokens.css`, `frontend/src/styles/base.css`,
Vue-компоненты и [ADR-008](adr/ADR-008-frontend-ui-kit.md). Эту инструкцию
не следует трактовать как доказательство визуальной приёмки каждой страницы.

## Визуальная иерархия

- Страницы используют существующие `PageShell`, семантические surface/border/text
  tokens и одинаковое расстояние между крупными секциями.
- Форма строится из групп с заголовком, короткой подсказкой и элементами управления.
  Поля в одной строке **выравниваются сверху**; поясняющий текст под одним
  полем не должен сдвигать соседний input/select.
- На небольших экранах многоколоночные формы переходят в одну колонку без
  горизонтального скролла. Таблицы с множеством колонок имеют явный контейнер
  с горизонтальной прокруткой и доступные подписи.
- Кнопки подтверждения, отмены и удаления визуально различаются функцией.
  Опасные операции не маскируются как обычные primary actions. Неиспользуемые
  действия не изображаются активными.

## Размеры и компоненты

| Вариант | CSS token | Применение |
| --- | --- | --- |
| Стандартный control | `--control-height: 42px` | input, select, обычные кнопки/иконки |
| Компактный control | `--control-height-compact: 36px` | pagination, ссылки и маленькие действия внутри таблиц |
| Крупный control | `--control-height-large: 44px` | основные действия мастеров, формы входа |
| Отступы | `--space-1` … `--space-12` | сетка и вертикальный ритм |
| Скругление | `--radius-md` / `--radius-lg` | элементы управления / панели |

**Не заменяйте механически** размеры checkbox (обычно 16px), badges,
строк таблиц и декоративных иконок на 42px. Размер выбирается по роли элемента.

## Переключение темы

Общий переключатель доступен в основной шапке Portal, на экране
входа/смены пароля и в шапке Docsify. Три режима —
`system` (по умолчанию), `light`, `dark`.
Он не зависит от контура SOURCE/TARGET, пользователя или backend.
Сохраняется только в localStorage браузера по ключу
`htp.ui.theme.v1`; `/docs/` использует тот же origin и ту же настройку.
Принудительная тема задаётся атрибутом `data-theme` на `html`,
системная тема — отсутствием этого атрибута и `prefers-color-scheme`.
Это не требует обновления страницы, перезапуска контейнера или CDN.

Нужны проверки переключения непосредственно на Portal, Login и Docsify,
на широкой и узкой ширине, с ошибками/disabled/таблицами/кодом.
Автоматическая проверка разметки и токенов **не равна** фактическому
визуальному измерению контраста.

## Цвета, доступность и состояния

- Не задавайте произвольные HEX в scoped styles. Используйте семантические
  `--color-*` для light/dark, поверхностей, границ, текста, alert и действий.
- Сохраняйте `:focus-visible`, контраст текста, семантические `label`,
  доступные имена для кнопок и элементов выбора, `role=status/alert`.
- `busy`, disabled, empty, error, success должны иметь текстовое объяснение,
  а не только изменение цвета. Во время асинхронного запроса устаревший ответ
  другого профиля не должен обновлять выбор.
- Element Plus и Lucide остаются предпочтительным UI-kit (ADR-008), но
  существующие token-driven компоненты допустимы без переписывания логики.

## Проверка изменений

1. Тесты `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`
   в `frontend/` и полный GitHub Quality Gate на **точном финальном SHA**.
2. Визуальная проверка на отдельном RC: desktop и narrow viewport, light/dark,
   длинные URL, подсказки, ошибки/disabled, tab/keyboard/focus и overflow.
3. Проверка поведения Harbor и Nexus после CSS-правок: выбор, добавление/удаление,
   digest, экспорт/импорт и отсутствие изменения backend/API.

CI не заменяет ручную визуальную проверку реальных браузеров и контуров.
